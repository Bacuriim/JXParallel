# The declarative UI model

`jxparallel-core` holds the small model that every screen ends up in, whether it was written in JXML,
generated by JXForge, or built by hand in Java. It is in package `com.jxparallel.ui`, uses nothing of
JavaFX, and runs on Java 8:

- `JXElement`: an immutable description of one node: a type (`column`, `button`, `input`...), props
  (`JXProps`) and children. `JXElement.of(type, props, children...)` builds one.
- `JXComponent`: an interface with one method, `JXElement render()`.
- `JXState<T>`: a value that notifies subscribers when it changes; `set` is thread safe and ignores a
  value equal to the current one.
- `JXLayouts` (`row`, `column`, `stack`) and `JXControls` (`button`, `input`, `checkbox`, `select`):
  builders of elements.
- `JXTheme` (package `com.jxparallel.ui.theme`): immutable design tokens, colors, spacing and a font
  (`JXTheme.clean()` is a ready one). It is a separate thing from the six tokens the native renderer
  paints with, `com.jxparallel.ui.native2d.JXTheme`, which is documented in [native-ui.md](native-ui.md).
- `JXNode` and `JXRenderer`: a mutable tree that mounts an element and patches it to a new one
  (`JXRenderer.mount(component)`, `JXRenderer.update(...)`). It holds types, props and children and
  paints nothing. The tests and the benchmarks use it; the native toolkit mounts elements into its own
  tree, `JXNativeNode`, which also has bounds and layout.

Drawing, layout, pointer and keyboard handling, focus, overlays and text editing are in
`jxparallel-ui`: `JXWindow.setContent(element)` reconciles an element tree into the mounted nodes and
paints it with Skia, NanoVG or the CPU painter. See [native-ui.md](native-ui.md). CSS is not part of
this model (JXML has its own named styles, see [jxforge.md](jxforge.md)).

## Example

```java
JXState<String> name = new JXState<String>("");

JXComponent form = () -> JXLayouts.column(16,
    JXControls.input(name.get(), "Your name"),
    JXControls.button("Continue", () -> name.set("submitted"))
);

JXNode root = JXRenderer.mount(form);                 // a tree of types and props, for tests
JXWindow window = new JXWindow("Form");
window.setContent(form.render());                     // the same description, drawn
window.show();
```

The model favors explicit state and immutable element descriptions over hidden lifecycle magic. Because
elements are immutable, an element that has not changed can be the same instance from one render to the
next, and the native reconcile skips it.
