# jxparallel-android

An Android backend for the native UI: the element tree is laid out and painted by `jxparallel-ui` exactly as on
the desktop, and drawn on an `android.graphics.Canvas`. Not part of the parent POM; it is built by a script, without
the Android Gradle plugin.

## What exists

| Piece | Role |
|---|---|
| `AndroidCanvasPainter` | `JXPainter` over `Canvas`/`Paint`: rects, rounded rects (gradients via `LinearGradient`), ovals, arcs, lines, triangles (`Path`), text, images (`Bitmap` cached by array identity), clip (`save`/`clipRect`), layer opacity (`saveLayerAlpha`) |
| `JXAndroidText` | The text metrics of the layout: installs a `JXTextEngine.LineMetrics` that asks `Paint` (same typefaces the painter draws with) |
| `JXAndroidView` | `View`: `setContent(JXElement)` / `setContent(Supplier<JXElement>)`, density-aware layout (dp), `onDraw`, touch to pointer events, keys and soft keyboard |
| `JXAndroidMath` | Android-free arithmetic (tested on the JVM) |
| `src/demo` | `JxHelloActivity`, `HelloController`, `hello.jxml` (compiled to `HelloView` at build time) |

In `jxparallel-ui`: `JXPainter` is public (the extension point of the renderer) and `JXFrame` is the public facade
(`mount`, `layout`, `paint`, `pointer`, `drag`, `key`, `character`, `tick`). Tested by `JXFrameTest`.

## Build and run

```
powershell -File jxparallel-android\build-apk.ps1 [-SkipMaven] [-Install]
```

Needs the Android SDK (platform `android-34`, build-tools `34.0.0`) and JDK 17. Steps: Maven (offline) compiles
core, ui and forge; `JXForge` turns `hello.jxml` into Java; `javac --release 8` against `android.jar`; the desktop
renderer classes are left out of the dex; `d8`; `aapt2 link`; `zipalign`; `apksigner` with a debug key generated by
`keytool`. Result: `build/jxhello.apk` (about 216 KB). `-Install` installs it with adb and starts it.

JVM check of the arithmetic: see the header of `src/test/java/com/jxparallel/android/JXAndroidMathCheck.java`.

## Android-incompatible parts of jxparallel-ui, and the cut

- `JXTextEngine` measured text with HarfBuzz through LWJGL (native, a font file). Now the HarfBuzz code lives in
  `JXHarfBuzz` (package `text`), loaded only when a font file was found. Without one, the engine asks the installed
  `LineMetrics` host for every size, bold or regular (it used to ask only for non-default sizes). Desktop behaviour
  is unchanged. So layout and painting agree: both use `Paint` with the system typeface (Roboto), measured at the
  physical size and divided by the density.
- `JXWindow`, `JXDisplay` (GLFW), `JXGdiSurface`, `JXNativeCall` (libffi/User32), `JXFileDialogs` (tinyfd),
  `JXSkia*`, `JXNanoVG*` (renderers), `JXSoftware*`/`JXGlyphs` (FreeType) are LWJGL/Skija classes. Nothing on the
  node/layout/paint path refers to them; the script excludes them from the dex.
- No `java.awt`, `javax.imageio` or `java.beans` anywhere in core, ui or forge's runtime path (ArchUnit already
  enforces AWT-free). `java.time`, `java.nio.file` need API 26: that is `minSdk`.

## Limits

- Verified on an x86_64 API 34 emulator (WHPX): the screen paints in the Material look; tapping the button
  changes the label, the switch toggles, and typed text reaches the text field (`docs/`).
- No touch scrolling or fling (the node tree has no scroll-by-gesture entry yet; scroll bars follow drags).
- A layer's blur radius is ignored (opacity works). No clipboard, no file dialogs, no accessibility bridge.
- Soft keyboard: plain characters, backspace, enter; no composing text/IME suggestions. Verified with
  `adb shell input text`, not with a real soft keyboard.
- Window insets and orientation changes are not handled specially (the view just re-lays out to its size).
- Touch acts on press, like a mouse click; long press is a secondary press.
- Only one density is supported per process (set when the first view is created).
